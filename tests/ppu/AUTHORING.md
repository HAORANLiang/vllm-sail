# PPU Serving Recipe & Preset Authoring Guide

This guide defines the authoring contract for `tests/ppu/recipes/` (`ppu-serving/v1`)
and `tests/ppu/policy/` (`ppu-test-policy/v1`) in **vLLM SAIL**. For the live generated
CI matrix and full serving preset catalog, see [README.md](README.md).

## 1. Directory Layout & Single Source of Truth

| Path | Ownership | Contents |
| --- | --- | --- |
| `tests/ppu/recipes/<org>/<model>.yaml` | Framework serving config | `vllm serve` serving arguments, allowlisted serving env vars, precision variants, hardware overrides, and named presets |
| `tests/ppu/policy/models/<slug>.yaml` | CI execution policy | Which variant/preset/hardware runs in PR `fast_sanity` or Nightly `model_sanity`, dummy/layer rules, GSM8K & micro-E2E stages |
| `tests/ppu/policy/datasets/<id>.yaml` | Evaluation dataset contract | Dataset version, few-shot count, filters, and expected sample count |
| `tests/ppu/README.md` | Auto-generated (never hand-edit) | Generated by `scripts/ci/ppu_recipe.py render-matrix --output tests/ppu/README.md` |

Every serving parameter belongs in exactly one place: the model's recipe YAML.
Every CI execution and dataset switch belongs in `tests/ppu/policy/`.

## 2. Recipe Boundaries (What Must Never Appear in Recipes)

A serving recipe describes **only** how to launch `vllm serve` for a public model.
`scripts/ci/ppu_recipe.py validate --all` fails closed on the following violations:

- **No policy-owned runtime flags**: Never hardcode `--enable-prefix-caching`,
  `--no-enable-prefix-caching`, `--disable-radix-cache`, `--load-format`,
  `--model-path`, `--tokenizer-path`, `--served-model-name`, `--host`, or `--port`.
  The executor injects prefix caching according to workload policy (enabled for
  sanity/evaluation, disabled for clean benchmarks) and resolves model/endpoint
  flags at runtime.
- **No invalid historical values**: Clean legacy parameters before onboarding. For
  example, `--gpu-memory-utilization` must be strictly in `(0.0, 1.0]` (never `0`),
  and `--reasoning-parser` / `--tool-call-parser` must match upstream vLLM parsers
  for the model family.
- **No client workload settings**: Do not put input/output sequence lengths (ISL/OSL),
  concurrency lists, prompt counts, or sampling/dataset parameters in recipes.
- **No runtime-mode or host-specific environment variables**: Variables such as
  `HF_HOME`, `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`, `CUDA_VISIBLE_DEVICES`,
  `VLLM_SERVER_DEV_MODE`, or `VLLM_USE_MODELSCOPE` are forbidden in recipes. Lower-level
  runtime/SDK variables (such as `DG_*` and `HGGC_*`) are allowed only when explicitly
  declared in `ppu.external_env`.
- **No private infrastructure or unreleased models**: Public recipes must never
  contain local/shared filesystem paths, internal domains or mirrors, IPv4 literals,
  physical hostnames, physical RDMA/IB interface names, credentials, or unreleased /
  non-public model identifiers. Use logical `ppu.assets`, public Hugging Face repo IDs,
  and topology placeholders instead.

## 3. Hardware x Precision Binding Contract

Each target T-Head Zhenwu hardware family supports native `bf16` alongside its
hardware-specific quantized precisions:

| Hardware ID | Device Name | Allowed Variant Precisions |
| --- | --- | --- |
| `zhenwu_m890` | Zhenwu M890 (`ZW-M890P`) | `bf16`, `mxfp4`, `mxfp4_fp8`, `fp4`, `fp8`, `fp8_channel`, `fp8_block`, `w8a8_fp8`, `w4a4_mxfp4` |
| `zhenwu_810e` | Zhenwu 810E (`PPU-ZW810E`) | `bf16`, `int8`, `w8a8_int8`, `w4a8_int8` |

- `bf16` is supported across all Zhenwu hardware families and is permitted for
  smaller or moderate-sized models that fit cleanly in `bf16` (with or without
  named presets). Omitting `hardware:` on a `bf16` variant keeps it portable across
  both `zhenwu_m890` and `zhenwu_810e` (both compatible hardware targets are
  expanded in `validate --all` and listed in the catalog even without
  `hardware_overrides`); set `hardware:` on the variant or preset when binding to a
  specific chip family.
- For large models (e.g., 100B+ / MoE flagships), prefer the target hardware's
  native quantized precisions (`mxfp4`/`fp8` on `zhenwu_m890`, `int8` on
  `zhenwu_810e`) for serving and performance presets.
- A single model recipe YAML can host `bf16` and multiple quantized variants
  across both hardware families. Use variant-level `hardware`, `assets`,
  `hf_model_id`, `golden_model_key`, `served_name`, and optional `topology`
  overrides so each checkpoint resolves cleanly without duplicating the recipe
  file.
- Every preset must match at least one compatible variant by hardware (and optional
  `variants:` allowlist). Cross-binding a `zhenwu_m890` preset/policy to an `int8`
  variant or a `zhenwu_810e` preset/policy to an `mxfp4`/`fp8` variant is rejected.

## 4. Standard Preset Slot Vocabulary & Topology Placeholders

Use the canonical preset slot names below so serving layouts stay uniform across
models and frameworks:

| Slot | Topology `kind` | Purpose | Required Placeholders / Rules |
| --- | --- | --- | --- |
| `prefill` | `single_node` (`nodes: 1`) | Prefill-optimized single-node layout (e.g., smaller TP width, `spec_decoding: false`) | None (placeholders and multi-node flags forbidden; effective local DP must equal global `--data-parallel-size`) |
| `decode` | `single_node` (`nodes: 1`) | Decode-optimized single-node layout (e.g., TP8 with MTP / speculative decoding enabled) | None (effective local DP must equal global `--data-parallel-size`) |
| `decode_ep` | `multi_node_ep` (`nodes >= 2`) | Multi-node DP+EP decode layout (e.g., 4-node DP32+EP+MTP) | Must enable `--enable-expert-parallel` and include `{master_addr}` and `{node_rank}` (`--nnodes` must match `topology.nodes`; for default internal-LB layouts where node 0 hosts the API server, launchers append `--headless` on non-zero node ranks, whereas `--data-parallel-hybrid-lb` runs an API server per node without `--headless` and `--data-parallel-external-lb` runs an API server per DP replica leader without `--headless`) |
| `pd_prefill` + `pd_decode` | `pd_disagg` (paired roles `prefill` + `decode`) | Disaggregated prefill/decode pair using `--kv-transfer-config` | Must be declared as a pair with matching `kv_role` (`kv_producer` / `kv_consumer`); for `MooncakeConnector`, wire `{kv_ip}` via `VLLM_HOST_IP`, `{ib_devices}` via `kv_connector_extra_config.device_name`, and `{kv_port}` on `pd_prefill` via `VLLM_MOONCAKE_BOOTSTRAP_PORT` (embedded bootstrap) or `kv_connector_extra_config.bootstrap_server_address` (external bootstrap); `pd_decode` receives `remote_bootstrap_addr` per request from the PD proxy |

Specialized single-node slots already in use by existing recipes (`dp_ep_low_latency`,
`prefill_long`, `eval_longctx`, `decode_nographs`, `tp8`) remain accepted for
compatibility; prefer the canonical four-scenario vocabulary above for new models.

### Placeholder Validation Contract

Supported topology placeholders are `{master_addr}`, `{master_port}`, `{node_rank}`,
`{kv_ip}`, `{kv_port}`, and `{ib_devices}`. During `validate --all` (both CPU checks
and PPU pin-UT real `vllm serve` argparse verification), `ppu_recipe.py` expands
100% of compatible `variant x preset` combinations, substitutes safe typed dummy
values (`127.0.0.1`, `29500`, `0`, `8998`, `rdma0`), and validates CLI syntax,
JSON objects, environment allowlists, effective world size (`DP x TP x PP x PCP`),
and redaction rules.

## 5. Three-Tier CI Gate Admission Rules

Adding a variant or preset to a recipe does **not** automatically allocate hardware
CI runners. Promotion follows three tiers:

1. **Tier 1 — Static Expansion & Catalog (Mandatory, 100% coverage)**
   Every compatible `variant x preset` must pass `ppu_recipe.py validate --all`,
   pass real `vllm serve` argparse checks in PPU pin-UT, and appear automatically in
   `tests/ppu/README.md` under `## Registered Serving Presets (Benchmark & Disagg Catalog)`.
2. **Tier 2 — PR `fast_sanity` (Selective single-node Zhenwu M890 execution)**
   Create or update a `tests/ppu/policy/models/<slug>.yaml` `fast_sanity` entry only
   when **both** conditions hold:
   - Hardware is `zhenwu_m890`, `topology.kind == "single_node"` (`nodes == 1`), and
     the target `hf_model_id` snapshot is confirmed present in the runner offline HF
     cache; and
   - The preset covers a distinct operator, parallelism, or feature execution path
     (for example, TP4 without MTP `prefill` vs TP8 with MTP `decode`, or single-node
     DP+EP).
   The single-node CI selector (`scripts/ci/ppu_e2e_select.py`) automatically skips
   `nodes > 1`, `pd_disagg`, oversized policies exceeding the single-node 8-card
   Zhenwu M890 runner limit, and unattached / non-M890 (`zhenwu_810e`) entries. Keep
   `zhenwu_810e` variants catalog-only until 810E storage and runners are ready, and
   keep `multi_node_ep` / `pd_disagg` static-only until multi-node K8s CI is onboarded.
3. **Tier 3 — Nightly `model_sanity` (One GSM8K gate per ready mainline precision)**
   Maintain one full-dataset GSM8K + micro-E2E `model_sanity` policy per ready
   mainline checkpoint (quantized or `bf16`, with a reviewed golden under
   `tests/e2e/models/_golden/`). Do **not** duplicate Nightly GSM8K runs for
   serving-parameter tuning presets.

## 6. Reference Exemplar & Local Verification

Use [`tests/ppu/recipes/zai-org/GLM-5.3.yaml`](recipes/zai-org/GLM-5.3.yaml) together
with [`tests/ppu/policy/models/glm-5.3.yaml`](policy/models/glm-5.3.yaml) and
[`tests/ppu/policy/models/glm-5.3-decode.yaml`](policy/models/glm-5.3-decode.yaml) as
the #0 full-scenario reference exemplar.

Run these commands from the repository root before opening or updating a PR:

```bash
# 1. Validate all recipes, policies, datasets, and 100% variant x preset expansions
python3 scripts/ci/ppu_recipe.py validate --all

# 2. Validate against the real vllm serve parser (inside a vLLM + vllm-sail runtime)
python3 scripts/ci/ppu_recipe.py validate --all --require-vllm-parser

# 3. Regenerate and verify tests/ppu/README.md
python3 scripts/ci/ppu_recipe.py render-matrix --output tests/ppu/README.md
python3 scripts/ci/ppu_recipe.py render-matrix --check

# 4. Run CPU unit tests covering recipes, selector, and workflows
python3 -m pytest tests/ut/test_ppu_recipe.py tests/ut/test_e2e_ppu_pipeline.py -q
```
